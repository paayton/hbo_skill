# 报关费对账（万海 / COSCO / MSC）

> **类目归属（2026-10-21 用户定版）**：用户说"对报关单/对报关费"即本技能。账单就是已跑通的报关费账单（宇中报关行 SHAYUNSHG 结算），其中"业务编号"列只是分属万海/COSCO/MSC 三家船公司，**核对逻辑与下方口径完全一致，无需区分船公司特殊处理**。

## 对账口径（2026-10-20 探库+用户定版，改规则必须问用户）

1. **三方对应**：宇中报关费账单 ↔ HBO 结算单位 `SHAYUNSHG`（上海宇中报关行，clientid **1332541068**，crm_client.clicode 解析验证 cliname_c=SHANGHAI YUNSHU CUSTOMS DECLARATION OFFICE）
2. **账单侧金额 = `合计(CNY)` 列**（报关费+联单费+查验费+加班费）。HBO 的"清关费/报关费"金额实测与账单合计构成一致（如 80 报关+150 联单 = 230 一条费用），**不是只核报关费列**
3. **系统侧** = clientid 1332541068 名下 `feename_c='清关费/报关费'`（feeid=1347041068）、rptype=1、未作废（isdeleted≠'Y'）、未销账（paypass='N'/空；其他=已销账剔除）的费用累加；fees.csv 同时带 `usercode`（createuser 换算的录入人英文代码，供操作列用）。**结算单位代码应收应付通用**：SHAYUNSHG / clientid 1332541068 不分应收（rptype=2）应付（rptype=1）——验证备注里提到的应收费用（如抵扣欠款，实证 2026-10-22：GOSZX25111440 应收 70）也用同一个代码查，只是 rptype 换 2
4. **判定 = 子集和（用户 2026-10-20 晚定版，同万海口径）**：拼单组账单合计在系统费用里**存在**（单笔等值或几笔之和等于账单合计）→ 一致；**系统多记的其他费用不构成异常**（实测：一工作单费用 320+140 两条，组账单 320 → 一致；按累加值比对会误报差额 140）。组内无费用 →「系统无X」；费用凑不出 →「系统Y」（系统只查到Y，用户习惯写法 2026-10-21 定版）。**不过滤 rpdate/cutoff**（工作单费用跨月累积，靠子集和吸收）。**数值不一致时两条补充动作（用户 2026-10-22 15:13 定版）**：① 把**查验费**也纳入系统侧累加再判定——账单合计常含查验费，系统可能录成"报关费+查验费"或分两条名目（2026-10-22 已确认案例：GOSZX26052364/GOSZX26042042 录了报关费+查验费、GOSZX26041656 录了报关费+拼箱查验费、GOSZX26062104 录了报关费+删单费， bills 均因此"差额"实为正确）；② **看报关费费用行后面的备注**——备注常写明费用构成/原因（事后修改、抵扣等），构成"差额"的第一解释权，备注能解释清楚的按正确备注、不再标异常（实证 2026-10-22：GOSZX26041425 系统仅 10、账单 80，备注写明"GOSZX25111440 报关行欠 70 直接抵扣（80-70=10）"，验证 25111440 确有应收 70 后判正）
5. **匹配键 = 提运单号**（账单"提运单号"列 → HBO `job_shipping_2026.sono`；注意"业务编号"列偶尔与提运单号不一致，必须用提运单号列）。**主匹配只用提运单号，绝不用箱号/合同号/业务编号做主匹配**（用户定版 2026-10-20）。**箱号兜底（用户 2026-10-21 定版"箱号是兜底方案"）**：提运单号在 HBO 查无（含拼单归组后仍无）时，用账单"集装箱号"列反查 `job_containers_2026.cntno`（多箱按非字母数字切分、≥6 位才收；JOIN job_shipping_2026 取 sono/blnoh），命中即采纳该工作单参与费用核对——报关费可能记在同箱的其他运单工作单上（实证：WA666V20064 查无，箱号 WHSU5249585 反查到 GOSZX26011720/sono WA666V20057，费用 80 应付未销账 → 一致）。箱号也查无才落到工作号尾段反查（尾段命中误配风险高，仅末位兜底）**HBO 无报关单号数据**（job_declinfo 表全空，2026-10-20 验证），报关单号仅展示不用来匹配。**作废单不算命中也别占查无名单（fetch 侧过滤 isdeleted='Y' 和 jobid=0，2026-10-22 实证）**：老表 job_shipping 的作废单可能带账单里的提运单号，若不过滤会把该运单挡在箱号兜底之外，输出"系统查无此工作单"（实证 177SPUPUS45631 被作废单 GOSZX26050826 挡掉，箱号 MSDU8028914 实际命中 GOSZX26050836）
6. **工作号 = blnoh**；jobid=0 的是假单/分单占位，剔除。一个运单可能命中多个工作单（分单 A/B），全部参与费用累加，显示取有费用的
7. **拼单（母子单）归组（用户 2026-10-20 定版）**： HBO 侧费用常按拼单组记在母单工作单上，账单侧每个运单列一行，单票比对必"异常"。必须用万海网页版查子单归组：
   - `scripts/wanhai_groups.py` 通过 Kimi WebBridge 驱动用户浏览器查 `https://es.wanhai.com/ces-api/#/BKG/e-Booking/BKGlist`
   - 规则：按客户SO查询，结果行带「查看子单」= 母单，点进去列表里全部客户SO 共享一个工作号（一组）；子单号直接查查不到（经由母单传递归属）；**COSU 等非万海平台前缀的运单网页查无**（订舱不在万海平台），这类拼单走系统侧归组
   - **非万海拼单系统侧归组（用户 2026-10-20/21 定版）**：尾字母单号归基数号（177GPUPUS43996A → 177GPUPUS43996）；COSCO 拼单去尾 2 位归组（COSU646355248001 → 6463552480，**长号在 HBO 查不到时自动用去尾基数号兜底再查**）；归组成员整组核金额，工作号填同一个
   - **同工作单数据驱动归组（2026-10-22 实证补充，用户当日定版"同工作号就该是一块"）**：上面两条规则盖不到的加拼单号（如 177SPUPUS45626+177SPUPUS45631，系统只认其中一个 sono、另一票靠箱号兜底命中同一 jobid）——reconcile 侧把解析到同一 jobid 的账单行并为一组整组核金额；**万海不除外**（09月两组 WA 同挂 GOSZX26073061，网页分成两组也不拆块——工作号是 ground truth，网页归组只是找组工具）；不并组会被分别判差额（80 vs 系统210、130 vs 系统210，而 80+130=210 实际一致）
   - **写出侧合并/归并必须按组键，不能只按工作号字符串（2026-10-22 教训）**：两个不同组同显一个工作号时（09月 WA666V80096 组与 WA666V80095 组同显 GOSZX26073061），按工作号合并单元格会把第二组的异常金额/操作判定整个遮盖掉，看起来像一大组。归并排序键和合并键都要带组键 gkey；凡是"判定用的集合"和"展示用的集合"必须同一过滤口径（作废单占 miss 挡住箱号兜底是同类的另一个坑）
   - **费用池覆盖全组组员（含不在本账单的组员，用户 2026-10-21 12:30 定版）**：万海组账单外组员（如 02月 WA666V20190 组的 WA666V20191）的工作单/费用也要取进来参与子集和——组员的报关费可能记在账单外组员的工作单上；**工作号显示仍只取账单内运单命中的单**；账单外组员清单由 build_row_groups 自动从 groups.json 发现，取数时把这些 sonos 一并传给 fetch_customs
   - 归组后整组比对（子集和判定见第 4 条）；一致 → 组内每行填同一工作号；不一致 → 整组黄色
8. **输出（用户定版）**：原账单内容不动；**账单自带 `工作号/异常金额/操作` 模板列（2月起的新格式）时结果写进原列，绝不重复插入**（重复列名会导致结果列被忽略）；账单没有这些列（如 9 月）才追加三列到末尾。异常行整行黄色（FFFF00）
   - **同工作号的行归并排列**（用户 2026-10-21 定版）：含加拼母子单（如 177GPUPUS43996A 挪到与 177GPUPUS43996 相邻，物理行 11+18 → 11+12）；组间按组内最早原行号排序、组内保持原序；无工作号的行互不合并留在原位；**序号列保留原值不动**（只动物理行位置，便于回溯原账单）；**同工作号组（加拼单号）工作号/异常金额/操作三列同span合并单元格展示**（用户 2026-10-21 16:05 定版；标注值只写组内首行，合并后一组一格）
   - 工作号：每组都填（母单+子单填同一个）；查无工作单留空
   - 异常金额：一致留空；否则**每组只在组内首行标一次**（用户 2026-10-21 15:34 定版"一次"），写「系统查无此工作单 / 系统无X / 系统Y」（用户习惯写法：差额不再写"差额X（票面-系统）"，直接标系统金额）；组内其余行留空，但整组仍黄色高亮。**结算单位错录侦测（用户 2026-10-21 17:40 定版）**：「系统无X」的组若别家客户名下有同名目应付费用（fetch 产出 fees_other.csv），备注「（代码错误，录在XXX名下金额）」——费用存在但结算单位录错，是最有行动价值的异常
   - 操作(员)（用户 2026-10-21 16:15 定版**吸取教训：只有异常组才写操作名，一致组留空**；只写组内首行，三列合并后一组一格）：**差额组** = 组内 HBO 应付费用行的录入人（app_users.usercode 英文代码，createuser→usercode 换算在 fetch_customs.py；多行去重逗号连接）；**系统无费用组** = 工作单的**操作**（委托单 sal_ordinfo.**serviceby**，用户 2026-10-21 16:31 在 HBO 工作单界面核对定版；**不是** documentby 文件人员、不是 opr_decby 报关操作——后两个字段实测多为空；fetch_customs 已换算英文代码写入 jobs.csv 的 op 列）；**查无工作单/一致组留空**。不要用账单"客户自编号"列（用户 2026-10-20 18:05 定版）
9. 只有人民币，无美金规则；销账费用剔除（沿用舱单费定版）。**拼单一致行不再红色高亮（用户 2026-10-21 12:08 定版）**，全表只有异常行黄色（FFFF00），红色已废除
10. **取数时滞**：文档部可能实时补录，异常偏多时重新 fetch 再判定

## 执行流程

0. 账单原件复制进工作区（桌面原件永不动）
1. 解析：`python scripts/customs_bill.py 账单.xls` → 账单_rows.csv（核对行数与账单一致；基准：09月 50 行 5250 元）
2. 取数（前提 `hbo_env.py to-proxy` + 用户重启 HBO 登录，见工作区 hbo-system.md）：
   `python scripts/fetch_customs.py --scripts-dir "<工作区>\hbo-reconcile-main\scripts" --rows 账单_rows.csv` → jobs.csv（含 **op 列=工作单操作(serviceby)** 英文代码）/ fees.csv。
   fetch_customs 内部三级兜底：提运单号精确/去空格/后缀正则 → **箱号反查 job_containers_2026**（需 rows.csv 带 container 列）→ 工作号尾段反查（末位，可疑时按箱号复核）
3. 拼单归组（前提 Kimi WebBridge 守护进程可用、用户浏览器已登录万海网页版）：
   先跑一次无 --groups 的 reconcile 圈出异常运单 → `python scripts/wanhai_groups.py --out groups.json --sonos <待查运单...>`（每个约 40-100 秒，页面很卡；建议增量分批跑，脚本每查完一个就落盘）
4. 对账：`python scripts/reconcile_customs.py --bill 账单.xls --rows 账单_rows.csv --jobs jobs.csv --fees fees.csv --groups groups.json --out 输出.xlsx`
5. 多月合并（用户要一份表单时）：逐月先各跑一份输出，再
   `python scripts/merge_months.py --out 合并.xlsx 02月=a.xlsx 03月=b.xlsx ...`
   → 只保留一个 sheet「全部」= 所有月份账单行放在一起（首列加月份）。**各月费用列布局不同
   （快递费/单证费/查验费…），按表头名对齐成统一列序，工作号/操作合并单元格随映射平移保留**。
   不要统计汇总页、不要月度 sheet，用户要的就是全部明细一张表
   （2026-10-21 两次定版）
5. 收尾：取数后必须 `python "<工作区>\hbo-reconcile-main\scripts\hbo_env.py" restore`（restore 后重开 HBO）；清理 inject_results.jsonl 里 >2MB 的行；抽查 1-2 个异常行手算复核

## 取数纪律（沿用 hbo-system.md）

固定 SQL 两段（2026-10-21 优化，无关数据在 SQL 层过滤，减少 HBO 往返）：工作单
（精确+去空格+后缀正则合成一条，2026 表+老表兜底）→ 费用（feeid 直接锁定名目、
rptype=1、未作废、未销账，不 JOIN 字典不拉其他名目）→ app_users 换算操作人。
不临时探库。代理空闲时让用户在 HBO 里点一下查询当载体。账单带工作号时勿用来历不明的值，一律以 HBO 反查为准。

**已实现（2026-10-22 代码化）**：① 费用名目运行时从 `fil_feeitem` 动态解析
'清关费/报关费' + 全部'%查验费%'名目（含拼箱查验费），同口径（rptype=1、未作废、未销账）
纳入子集和判定；② 备注列经 information_schema 探测后随费用行带出——**实证列名是
`remarks`**（stl_arap_2026，152 列，2026-10-22 探明；fees.csv 增加 remark 列，
"系统Y/系统无X"组的异常文案自动附「备注：…」供判正）；③ 新增 fees_recv.csv 拉同代码
（SHAYUNSHG）应收 rptype=2 备查，验证备注里的抵扣/欠款（应收应付同代码，rptype 区分；
2026-10-22 实测 26 年工作单下应收均为 0，抵扣类应收挂在 25 年老工作单上，需按备注
指向单独查）

## 已知边界

- 万海网页查询偶发慢加载：found=false 的运单要重试 1-2 次再下结论；子单号直接查查不到是正常行为
- 非万海平台订舱（COSU 前缀等）查不到子单，拼单无法自动归组
- .xls 原件输出为 xlsx（值一致，格式不保留，交付时说明）
