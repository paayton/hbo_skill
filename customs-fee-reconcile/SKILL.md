# 报关费对账（万海 / COSCO / MSC）

> **类目归属（2026-10-21 用户定版）**：用户说"对报关单/对报关费"即本技能。账单就是已跑通的报关费账单（宇中报关行 SHAYUNSHG 结算），其中"业务编号"列只是分属万海/COSCO/MSC 三家船公司，**核对逻辑与下方口径完全一致，无需区分船公司特殊处理**。

## 对账口径（2026-10-20 探库+用户定版，改规则必须问用户）

1. **三方对应**：宇中报关费账单 ↔ HBO 结算单位 `SHAYUNSHG`（上海宇中报关行，clientid **1332541068**，crm_client.clicode 解析验证 cliname_c=SHANGHAI YUNSHU CUSTOMS DECLARATION OFFICE）
2. **账单侧金额 = `合计(CNY)` 列**（报关费+联单费+查验费+加班费）。HBO 的"清关费/报关费"金额实测与账单合计构成一致（如 80 报关+150 联单 = 230 一条费用），**不是只核报关费列**
3. **系统侧** = clientid 1332541068 名下 `feename_c='清关费/报关费'`（feeid=1347041068）、rptype=1、未作废（isdeleted≠'Y'）、未销账（paypass='N'/空；其他=已销账剔除）的费用累加；fees.csv 同时带 `usercode`（createuser 换算的录入人英文代码，供操作列用）
4. **判定 = 子集和（用户 2026-10-20 晚定版，同万海口径）**：拼单组账单合计在系统费用里**存在**（单笔等值或几笔之和等于账单合计）→ 一致；**系统多记的其他费用不构成异常**（实测：一工作单费用 320+140 两条，组账单 320 → 一致；按累加值比对会误报差额 140）。组内无费用 →「系统金额无票面X」；费用凑不出 →「差额X（票面-系统，负值=系统多）」。**不过滤 rpdate/cutoff**（工作单费用跨月累积，靠子集和吸收）
5. **匹配键 = 提运单号**（账单"提运单号"列 → HBO `job_shipping_2026.sono`；注意"业务编号"列偶尔与提运单号不一致，必须用提运单号列）。**只用提运单号匹配，绝不用箱号/合同号/业务编号查**（用户定版 2026-10-20）。**HBO 无报关单号数据**（job_declinfo 表全空，2026-10-20 验证），报关单号仅展示不用来匹配
6. **工作号 = blnoh**；jobid=0 的是假单/分单占位，剔除。一个运单可能命中多个工作单（分单 A/B），全部参与费用累加，显示取有费用的
7. **拼单（母子单）归组（用户 2026-10-20 定版）**： HBO 侧费用常按拼单组记在母单工作单上，账单侧每个运单列一行，单票比对必"异常"。必须用万海网页版查子单归组：
   - `scripts/wanhai_groups.py` 通过 Kimi WebBridge 驱动用户浏览器查 `https://es.wanhai.com/ces-api/#/BKG/e-Booking/BKGlist`
   - 规则：按客户SO查询，结果行带「查看子单」= 母单，点进去列表里全部客户SO 共享一个工作号（一组）；子单号直接查查不到（经由母单传递归属）；**COSU 等非万海平台前缀的运单网页查无**（订舱不在万海平台），这类拼单走系统侧归组
   - **非万海拼单系统侧归组（用户 2026-10-20/21 定版）**：尾字母单号归基数号（177GPUPUS43996A → 177GPUPUS43996）；COSCO 拼单去尾 2 位归组（COSU646355248001 → 6463552480，**长号在 HBO 查不到时自动用去尾基数号兜底再查**）；归组成员整组核金额，工作号填同一个
   - 归组后整组比对（子集和判定见第 4 条）；一致 → 组内每行填同一工作号；不一致 → 整组黄色
8. **输出（用户定版）**：原账单内容不动；**账单自带 `工作号/异常金额/操作` 模板列（2月起的新格式）时结果写进原列，绝不重复插入**（重复列名会导致结果列被忽略）；账单没有这些列（如 9 月）才追加三列到末尾。异常行整行黄色（FFFF00）
   - **同工作号的行归并排列**（用户 2026-10-21 定版）：含加拼母子单（如 177GPUPUS43996A 挪到与 177GPUPUS43996 相邻，物理行 11+18 → 11+12）；组间按组内最早原行号排序、组内保持原序；无工作号的行互不合并留在原位；**序号列保留原值不动**（只动物理行位置，便于回溯原账单）；**工作号列相同值合并单元格展示**
   - 工作号：每组都填（母单+子单填同一个）；查无工作单留空
   - 异常金额：一致留空；否则写「系统查无此工作单 / 系统金额无票面X / 差额X（票面-系统）」
   - 操作(员) = 组内 HBO **应付费用行的录入人**（app_users.usercode 英文代码，如 KATELUO/ROSIEQIN；createuser→usercode 换算在 fetch_customs.py 里做），组内多行去重逗号连接；**组内无费用行则留空**（用户 2026-10-20 18:05 定版：**不要用账单"客户自编号"列**）
9. 只有人民币，无美金规则；销账费用剔除（沿用舱单费定版）。**拼单一致行不再红色高亮（用户 2026-10-21 12:08 定版）**，全表只有异常行黄色（FFFF00），红色已废除
10. **取数时滞**：文档部可能实时补录，异常偏多时重新 fetch 再判定

## 执行流程

0. 账单原件复制进工作区（桌面原件永不动）
1. 解析：`python scripts/customs_bill.py 账单.xls` → 账单_rows.csv（核对行数与账单一致；基准：09月 50 行 5250 元）
2. 取数（前提 `hbo_env.py to-proxy` + 用户重启 HBO 登录，见工作区 hbo-system.md）：
   `python scripts/fetch_customs.py --scripts-dir "<工作区>\hbo-reconcile-main\scripts" --rows 账单_rows.csv` → jobs.csv / fees.csv
3. 拼单归组（前提 Kimi WebBridge 守护进程可用、用户浏览器已登录万海网页版）：
   先跑一次无 --groups 的 reconcile 圈出异常运单 → `python scripts/wanhai_groups.py --out groups.json --sonos <待查运单...>`（每个约 40-100 秒，页面很卡；建议增量分批跑，脚本每查完一个就落盘）
4. 对账：`python scripts/reconcile_customs.py --bill 账单.xls --rows 账单_rows.csv --jobs jobs.csv --fees fees.csv --groups groups.json --out 输出.xlsx`
5. 多月合并（用户要一份表单时）：逐月先各跑一份输出，再
   `python scripts/merge_months.py --out 合并.xlsx 02月=a.xlsx 03月=b.xlsx ...`
   → 只保留一个 sheet「全部」= 所有月份账单行放在一起（首列加月份，逐月平移保留
   工作号合并）。**不要统计汇总页、不要月度 sheet，用户要的就是全部明细一张表
   （2026-10-21 两次定版）**
5. 收尾：取数后必须 `python "<工作区>\hbo-reconcile-main\scripts\hbo_env.py" restore`（restore 后重开 HBO）；清理 inject_results.jsonl 里 >2MB 的行；抽查 1-2 个异常行手算复核

## 取数纪律（沿用 hbo-system.md）

固定 SQL 两段（2026-10-21 优化，无关数据在 SQL 层过滤，减少 HBO 往返）：工作单
（精确+去空格+后缀正则合成一条，2026 表+老表兜底）→ 费用（feeid 直接锁定名目、
rptype=1、未作废、未销账，不 JOIN 字典不拉其他名目）→ app_users 换算操作人。
不临时探库。代理空闲时让用户在 HBO 里点一下查询当载体。账单带工作号时勿用来历不明的值，一律以 HBO 反查为准。

## 已知边界

- 万海网页查询偶发慢加载：found=false 的运单要重试 1-2 次再下结论；子单号直接查查不到是正常行为
- 非万海平台订舱（COSU 前缀等）查不到子单，拼单无法自动归组
- .xls 原件输出为 xlsx（值一致，格式不保留，交付时说明）
